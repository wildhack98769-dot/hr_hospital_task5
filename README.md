# Hospital Management

Модуль `hr_hospital` додає в Odoo базову систему керування госпіталем: облік пацієнтів, лікарів, прийомів, діагнозів, історії призначення персонального лікаря та звітності.

## Основні можливості

- Ведення карток пацієнтів із контактами, фото, датою народження, групою крові, Rh-фактором, страховим полісом та персональним лікарем.
- Облік лікарів зі спеціалізацією, категорією, системним користувачем, фото та медичною інформацією.
- Підтримка інтернів і наставників: інтерни визначаються через категорію лікаря, а наставником може бути тільки лікар, який не є інтерном.
- Планування візитів пацієнтів до лікарів із датою, статусом, діагнозом та епікризом.
- Статуси візитів: `Planned`, `Done`, `Cancelled`.
- Захист завершених візитів від зміни ключових полів, видалення та архівації.
- Ієрархічний довідник захворювань із групами, підкатегоріями, ICD-кодами та кольоровими мітками.
- Історія призначення лікарів пацієнтам.
- Масове перепризначення персонального лікаря для вибраних пацієнтів.
- Дашборд із кількістю пацієнтів, лікарів, візитів, діагнозів, категорій лікарів та записів історії.
- Аналіз візитів через списки, форми та аналітичні представлення.
- PDF-звіти по лікарях і статистиці захворювань.
- Українська локалізація через `i18n/uk_UA.po`.

## Меню модуля

Після встановлення модуль додає головне меню **Hospital**.

Основні розділи:

- **Patients** - картки пацієнтів.
- **Doctors** - картки лікарів.
- **Visits / Visits Log** - журнал прийомів.
- **Visits / Visits Analysis** - аналіз прийомів.
- **Configuration / Diseases** - довідник захворювань.
- **Configuration / Doctor Qualifications** - категорії та кваліфікації лікарів.
- **Configuration / Doctor History** - історія призначення лікарів пацієнтам.

## Бізнес-логіка

### Пацієнти

Пацієнт має персонального лікаря, контактні дані, медичну інформацію та історію призначень лікарів. Із картки пацієнта можна відкрити всі його візити або швидко створити новий візит із попередньо заповненим пацієнтом і персональним лікарем.

### Лікарі

Лікар має спеціалізацію, категорію та може бути пов'язаний із користувачем Odoo. Категорія може позначати лікаря як інтерна. Для інтерна можна вибрати наставника, але наставником не може бути інший інтерн або сам лікар.

### Візити

Візит пов'язує пацієнта, лікаря, дату прийому та діагноз. Для завершеного візиту автоматично фіксується фактична дата, якщо вона не була задана вручну.

Для завершених візитів заборонено:

- змінювати дату, час, лікаря або пацієнта;
- видаляти запис;
- архівувати запис;
- переводити запис назад у запланований або скасований стан.

### Захворювання

Довідник захворювань підтримує деревоподібну структуру. Групові записи використовуються як категорії, а конкретні захворювання можна вибирати у візитах.

## Звіти та майстри

- **Visit Report Wizard** - формує список візитів за лікарями, пацієнтами, періодом, статусом і діагнозом.
- **Disease Report Wizard** - генерує PDF-звіт зі статистикою захворювань за вибраний період, лікарів і діагнози.
- **Disease Month Report Wizard** - відкриває згрупований список візитів за захворюваннями за період.
- **Mass Reassign Doctor Wizard** - масово змінює персонального лікаря для вибраних пацієнтів.
- **Doctor Report (PDF)** - PDF-звіт по лікарю з пацієнтами та історією візитів.

## Встановлення

1. Скопіюйте модуль у директорію custom addons вашого Odoo:

   ```bash
   custom_addons/hr_hospital
   ```

2. Переконайтеся, що шлях до `custom_addons` додано в `addons_path` конфігурації Odoo.

3. Оновіть список застосунків:

   ```bash
   odoo-bin -c odoo.conf -u base
   ```

4. У режимі розробника знайдіть застосунок **Hospital Management** та встановіть його.

Для оновлення вже встановленого модуля:

```bash
odoo-bin -c odoo.conf -u hr_hospital
```

## Залежності

Модуль залежить від стандартних модулів Odoo:

- `base`
- `hr`

Версія модуля: `19.0.1.0.0`.

## Демодані

Модуль містить демодані для швидкого тестування:

- захворювання;
- категорії лікарів;
- лікарі;
- пацієнти;
- візити;
- історія призначення лікарів.

Демодані завантажуються при встановленні модуля в базі, де увімкнено demo data.

## Структура модуля

```text
hr_hospital/
├── models/       # бізнес-моделі: пацієнти, лікарі, візити, захворювання, дашборд
├── views/        # XML-представлення, меню та дії
├── wizard/       # майстри для звітів і масових операцій
├── report/       # QWeb/PDF-звіти
├── security/     # права доступу
├── demo/         # демодані
├── data/         # базові дані
├── i18n/         # переклади
└── static/       # іконки, зображення та SCSS
```

## Права доступу

Доступ до основних моделей і майстрів надано користувачам групи `base.group_user`. Користувачі цієї групи можуть читати, створювати, редагувати та видаляти записи, окрім випадків, обмежених бізнес-логікою модуля.
